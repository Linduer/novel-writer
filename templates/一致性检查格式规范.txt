# ============================================================
# 一致性检查格式规范 v1.0
# 检查新生成的内容是否与所有规范设定相符
# ============================================================

# ════════════════════════════════════════════════════════════
#  一、检查维度
# ════════════════════════════════════════════════════════════

一致性检查覆盖9个维度：

| 维度 | 检查内容 | 严重程度 | 依据规范 |
|------|----------|----------|----------|
| 禁止内容 | 违禁词汇、半角标点 | error | 全局 |
| 角色一致性 | 说话风格、禁止称呼 | error | 角色档案、说话风格、别名系统 |
| 数字一致性 | 精确数字使用 | error | 数字记忆格式规范 |
| 伏笔一致性 | 伏笔ID、推进/回收 | warning | 伏笔格式规范 |
| 约束一致性 | Tier1/Tier2/Tier3 | error | 约束系统 |
| 地点一致性 | 地点名称、设施 | warning | 地点档案格式规范 |
| 能力一致性 | 境界、天赋、设施 | warning | 能力体系格式规范 |
| 风格一致性 | 粗口、段落长度 | warning | 说话风格格式规范 |
| 字数检查 | 1000-1500字 | error | 细纲格式规范 |


# ════════════════════════════════════════════════════════════
#  二、检查流程
# ════════════════════════════════════════════════════════════

生成后检查流程：

1. LLM生成章节草稿
2. 调用 check_chapter() 进行一致性检查
3. 如果有error级别问题 → 返回给LLM修改
4. 如果只有warning级别问题 → 标记但允许通过
5. 生成检查报告
6. 保存检查结果到 chapter/metadata.json


# ════════════════════════════════════════════════════════════
#  三、检查项详细说明
# ════════════════════════════════════════════════════════════

## 1. 禁止内容检查（error）

检查以下禁止内容：
- "命运的齿轮开始转动"
- "这一刻，他终于明白了"
- "他/她"
- "（未完待续）"
- "（欲知后事如何）"
- 半角标点后接中文

## 2. 角色一致性检查（error）

检查角色的：
- 说话风格是否符合signature_style
- 是否使用了forbidden_patterns中的表达
- 是否使用了forbidden_calls中的称呼
- 自称是否与self_call一致

## 3. 数字一致性检查（error）

检查数字记忆中的精确数字：
- 密码/代码是否正确使用
- 日期/生日是否准确
- 金额/数量是否一致
- 坐标/位置是否正确

## 4. 伏笔一致性检查（warning）

检查伏笔：
- 是否有超时未解决的伏笔
- 伏笔推进/回收是否在正确章节
- 伏笔ID引用是否正确

## 5. 约束一致性检查（error）

检查约束：
- Tier1约束是否被违反
- Tier2约束是否被违反
- Tier3约束是否被违反

## 6. 地点一致性检查（warning）

检查地点：
- 地点名称是否正确
- 设施名称是否正确
- 地点描述是否与设定一致

## 7. 能力一致性检查（warning）

检查能力：
- 境界名称是否正确
- 天赋描述是否一致
- 设施解锁状态是否正确

## 8. 风格一致性检查（warning）

检查风格：
- 是否有粗口/违禁词
- 段落是否过长（>500字）
- 文风是否与设定一致

## 9. 字数检查（error）

检查字数：
- 中文字数是否在1000-1500之间
- 过少（<1000）为error
- 过多（>2000）为warning


# ════════════════════════════════════════════════════════════
#  四、严重程度定义
# ════════════════════════════════════════════════════════════

| 级别 | 说明 | 处理方式 |
|------|------|----------|
| error | 必须修复，否则不能通过 | 返回给LLM修改 |
| warning | 建议修复，但允许通过 | 标记提醒 |
| info | 仅供参考，无需处理 | 记录日志 |


# ════════════════════════════════════════════════════════════
#  五、检查报告格式
# ════════════════════════════════════════════════════════════

报告包含：
1. 检查结果（通过/未通过）
2. 摘要（总问题数、错误数、警告数）
3. 详细问题列表（按严重程度分组）
4. 每个问题的类型、消息、建议


# ════════════════════════════════════════════════════════════
#  六、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 角色档案格式规范
   - 检查角色一致性时读取角色档案
   - 检查说话风格时读取说话风格
   - 检查别名时读取别名系统

2. 数字记忆格式规范
   - 检查数字一致性时读取数字记忆
   - 检查数字是否正确使用

3. 伏笔格式规范
   - 检查伏笔一致性时读取伏笔数据
   - 检查伏笔超时/推进/回收

4. 约束系统
   - 检查约束一致性时读取约束数据
   - 检查Tier1/Tier2/Tier3约束

5. 地点档案格式规范
   - 检查地点一致性时读取地点档案
   - 检查地点名称/设施

6. 能力体系格式规范
   - 检查能力一致性时读取能力数据
   - 检查境界/天赋/设施

7. 说话风格格式规范
   - 检查风格一致性时读取说话风格
   - 检查catchphrases/forbidden_patterns

8. 细纲格式规范
   - 检查字数时参考细纲的word_count
   - 检查核心事件是否完成

9. 上下文引擎
   - 检查结果注入下章prompt
   - 帮助LLM避免重复错误


# ════════════════════════════════════════════════════════════
#  七、查询命令
# ════════════════════════════════════════════════════════════

python main.py check ch0095              # 检查第95章一致性
python main.py check ch0095 --fix        # 检查并尝试自动修复
python main.py check --all               # 检查所有章节
python main.py check --report            # 生成检查报告
python main.py check --foreshadowing     # 只检查伏笔一致性
python main.py check --character 沈浮    # 只检查特定角色一致性
