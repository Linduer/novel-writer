# ════════════════════════════════════════════════════════════
#  一、为什么需要爽点审查
# ════════════════════════════════════════════════════════════

网文读者追求"爽感"，不管理爽点会导致：
  1. 连续几万字没有爽点，读者弃书
  2. 爽点太密集，读者审美疲劳
  3. 高潮间隔不均匀，节奏混乱
  4. 打脸/反转/装逼等爽点类型单一

# ════════════════════════════════════════════════════════════
#  二、爽点类型
# ════════════════════════════════════════════════════════════

## 主要爽点类型

| 类型     | 说明                   | 示例                        |
|----------|------------------------|-----------------------------|
| 打脸     | 证明对方错了           | 公输瑶"它不是机器"          |
| 装逼     | 展示隐藏实力           | 三姆三星觉醒                |
| 反转     | 剧情180度转弯          | 敖涸归队                    |
| 逆袭     | 从弱到强，反败为胜     | 沈浮从负债到免票            |
| 收获     | 获得新能力/物品/伙伴   | 解锁造浪池、打捞新英灵      |
| 守护     | 保护重要的人           | 三姆"把所有人挡在身后"      |
| 牺牲     | 为他人付出             | 贾克殉园                    |
| 团聚     | 分离后重逢             | 沧溟与中枢告别              |
| 揭秘     | 真相大白               | 洪水真账揭晓                |
| 报仇     | 复仇成功               | 打败水老大                  |
| 成就     | 达成重要目标           | 乐园开业、免票              |
| 认可     | 被重要人物认可         | 沧溟"船给你，班你接"        |

## 爽点强度

| 等级 | 说明 | 字数占比 | 示例 |
|------|------|----------|------|
| S级  | 全书高潮 | 1-2章 | 终战、免票 |
| A级  | 卷级高潮 | 5-10章 | 满潮夜、方舟点火 |
| B级  | 章节高潮 | 20-50章 | 打脸、逆袭 |
| C级  | 小爽点 | 100-200章 | 收获、认可 |
| D级  | 微爽点 | 每章都有 | 吐槽、日常 |


# ════════════════════════════════════════════════════════════
#  三、节奏分布模型
# ════════════════════════════════════════════════════════════

## 30/40/30 结构（推荐）

每个卷的节奏分布：
  前30%：铺垫+小爽点（建立期待）
  中40%：冲突+中爽点（制造张力）
  后30%：高潮+大爽点（释放张力）

## 单章节奏结构

每个章节的节奏分布：
  开头10%：承接上章+引入本章
  中间70%：核心内容+爽点
  结尾20%：收尾+钩子（让读者想看下一章）

## 爽点间隔规则

| 爽点等级 | 最大间隔 | 说明 |
|----------|----------|------|
| S级      | 1卷      | 每卷至少一个S级爽点 |
| A级      | 100章    | 每100章至少一个A级爽点 |
| B级      | 30章     | 每30章至少一个B级爽点 |
| C级      | 10章     | 每10章至少一个C级爽点 |
| D级      | 1章      | 每章都有D级爽点 |


# ════════════════════════════════════════════════════════════
# 四、字段说明
# ════════════════════════════════════════════════════════════

## 章节爽点记录

每章写完后，记录爽点信息：

- chapter:            章节号
- satisfaction_points: 本章爽点列表
    - type:           爽点类型（见取值表）
    - strength:       爽点强度（S/A/B/C/D）
    - description:    爽点描述（一句话）
    - target:         爽点对象（谁被打脸/被认可/被守护）
    - executor:       爽点执行者（谁完成了这个爽点）
    - trigger:        爽点触发（什么事件触发了这个爽点）

## 卷级爽点统计

每卷写完后，统计爽点分布：

- volume:             卷号
- total_chapters:     本卷总章数
- satisfaction_stats: 爽点统计
    - S级:            数量
    - A级:            数量
    - B级:            数量
    - C级:            数量
    - D级:            数量
- pacing_distribution: 节奏分布
    - 铺垫:          章节数
    - 冲突:          章节数
    - 高潮:          章节数
    - 过渡:          章节数
- satisfaction_gaps:  爽点间隔
    - max_gap:        最大间隔（章）
    - avg_gap:        平均间隔（章）


# ════════════════════════════════════════════════════════════
#  五、审查规则
# ════════════════════════════════════════════════════════════

## 爽点密度审查

| 规则 | 说明 | 触发条件 |
|------|------|----------|
| 连续无爽点 | 连续5章没有C级以上爽点 | 警告 |
| 爽点过密 | 连续3章都有A级以上爽点 | 警告 |
| 爽点单一 | 连续5章都是同类型爽点 | 建议 |
| 高潮间隔过长 | A级爽点间隔超过100章 | 警告 |

## 节奏分布审查

| 规则 | 说明 | 触发条件 |
|------|------|----------|
| 铺垫过长 | 铺垫占比超过40% | 建议 |
| 高潮过短 | 高潮占比低于20% | 建议 |
| 过渡过多 | 过渡章节超过15% | 警告 |

## 爽点质量审查

| 规则 | 说明 | 触发条件 |
|------|------|----------|
| 打脸无铺垫 | 打脸爽点没有前置铺垫 | 警告 |
| 反转太突然 | 反转爽点没有伏笔 | 警告 |
| 牺牲无意义 | 牺牲爽点没有推动剧情 | 建议 |

#  七、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 场景切片
   - 场景的 tension_level → 爽点的 strength
   - 场景的 emotion → 爽点的 type

2. 伏笔系统
   - 爽点的 trigger → 伏笔的引入/推进/回收
   - 打脸/反转爽点 → 伏笔的回收

3. 角色档案
   - 爽点的 executor → 角色的 growth_arc
   - 爽点的 target → 角色的 constraints

4. 章节记忆
   - 每章的爽点 → memory.json 中的 satisfaction字段

5. 上下文引擎
   - 当前卷的爽点分布 → 注入prompt
   - 帮助LLM安排下一章的爽点
