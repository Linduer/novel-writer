# ============================================================
# 行文风格格式规范 v1.0
# 定义整篇小说的写作风格、语言习惯、修辞手法
# ============================================================

# ════════════════════════════════════════════════════════════
#  一、字段分级（对应三级约束体系）
# ════════════════════════════════════════════════════════════

所有字段按"可变性"分为三档，冲突时高档优先。

## 第一档：基础性（绝对不可偏离）— Tier1

一旦写定永远不改，写入 Tier1 基础约束。

  narrative_voice         叙事声音（第一人称/第三人称/限制视角）
  core_tone               核心基调（轻松/沉重/荒诞/热血）
  forbidden_styles        绝对不能出现的风格
  writing_rules           硬规则（如"不许用'突然'"）

## 第二档：可演变（随行文自然变化）— Tier2

会随剧情发展而变化，在 growth_arc 中分阶段记录。

  humor_style             幽默风格（随剧情变化）
  emotional_depth         情感深度（随剧情变化）
  pacing_patterns         节奏模式（随剧情变化）

## 第三档：可偏离（根据行文情况调整）— Tier3

每章可灵活调整，写完归档，下次覆盖。

  chapter_tone            章节基调（每章可不同）
  scene_pacing            场景节奏（快/慢/交替）
  descriptive_density     描写密度（稀疏/适中/密集）
  dialogue_ratio          对话比例（高/中/低）


# ════════════════════════════════════════════════════════════
#  二、字段说明
# ════════════════════════════════════════════════════════════

## 核心身份
- name:                 小说名（与项目一致）

## 基础字段（Tier1）
- narrative_voice:       叙事声音
                        例："第三人称限制视角，以沈浮为主视角"
                        例："偶尔切换到其他角色视角（需在细纲中注明）"

- core_tone:             核心基调
                        例："番茄爽文+末世生存+欢乐日常"
                        例："笑中带泪，苦中作乐"

- forbidden_styles:      绝对不能出现的风格
                        例："不许虐主"
                        例："不许无脑后宫"
                        例："不许过度黑暗"

- writing_rules:         硬规则
                        例："每章必须有至少一个爽点"
                        例："每章必须有至少一个笑点"
                        例："章尾必须有钩子"

## 可演变字段（Tier2）
- humor_style:           幽默风格
                        例："反差萌（末世+欢乐）"
                        例："吐槽（主角/中枢）"
                        例："日常崩坏（孩子们）"

- emotional_depth:       情感深度
                        例："表面轻松底层沉重"
                        例："不直接写悲伤，通过动作和细节流露"

- pacing_patterns:       节奏模式
                        例："30%日常铺垫+40%高潮爆发+30%余韵回味"
                        例："每30章1个S级爽点"

## 可偏离字段（Tier3）
- chapter_tone:          章节基调
                        例："战斗章/日常章/揭秘章/情感章"
                        每章根据细纲调整

- scene_pacing:          场景节奏
                        例："快-慢-快交替"
                        例："紧张场景短句连发，抒情场景长句铺陈"

- descriptive_density:   描写密度
                        例："动作场景稀疏，环境场景适中，情感场景密集"

- dialogue_ratio:        对话比例
                        例："日常章60%，战斗章40%，揭秘章50%"


# ════════════════════════════════════════════════════════════
#  三、叙事视角
# ════════════════════════════════════════════════════════════

## 主视角
  type:                   第三人称限制视角
  protagonist:            沈浮
  camera_position:        跟随主角，偶尔切换
  knowledge_limit:        读者只知道主角知道的（制造悬念）

## 视角切换规则
  触发条件:               细纲中明确注明"视角切换至XXX"
  切换频率:               每卷最多3-5次
  禁止事项:               不许频繁切换造成混乱
  切换标记:               换行+空行+新视角角色名

## 章节视角分配
  日常章:                 100%主角视角
  战斗章:                 80%主角视角+20%队友视角
  揭秘章:                 可切换到反派视角（制造悬念）
  情感章:                 可切换到配角视角（制造感动）


# ════════════════════════════════════════════════════════════
#  四、语言风格
# ════════════════════════════════════════════════════════════

## 基础语言
  口语化程度:             高（贴近角色说话）
  书面语程度:             低（避免文绉绉）
  网络用语:               适度（不堆砌）
  古风用语:               仅特定角色（敖涸）

## 用词原则
  简洁:                   能用一个词不用两个词
  精准:                   用最准确的词，不用"差不多"的词
  生动:                   用具体名词，少用抽象名词
  节奏:                   短句为主，长句点缀

## 禁用词表
  类型一_万能词:          "突然"、"忽然"、"不禁"、"忍不住"
  类型二_空洞词:          "感觉"、"好像"、"似乎"、"仿佛"
  类型三_过度形容:        "美丽的"、"漂亮的"、"好看的"（需具体化）
  类型四_说教词:          "道理"、"意义"、"人生"（需情节体现）


# ════════════════════════════════════════════════════════════
#  五、修辞手法
# ════════════════════════════════════════════════════════════

## 必用修辞
  反差:                   末世+欢乐，沉重+搞笑，危机+日常
  吐槽:                   主角/中枢的吐槽是标志性风格
  金句:                   每章至少一句可以被读者记住的话
  伏笔:                   每章至少一个伏笔（大小均可）

## 适量修辞
  比喻:                   用具体事物比喻抽象感受
  排比:                   用于强调和节奏感
  夸张:                   用于搞笑和爽点
  拟人:                   用于环境描写和物品描写

## 禁用修辞
  过度渲染:               不许堆砌形容词
  无病呻吟:               不许为赋新词强说愁
  说教:                   不许通过角色之口说教


# ════════════════════════════════════════════════════════════
#  六、节奏控制
# ════════════════════════════════════════════════════════════

## 章节节奏
  目标字数:               2500-3500字/章
  开头:                   前3句必须抓人（钩子）
  中段:                   至少1个爽点/笑点/揭秘点
  结尾:                   必须有钩子（悬念/期待/反转）

## 句子节奏
  快节奏:                 短句连发（<10字），用于战斗/紧张/搞笑
  慢节奏:                 长句铺陈（>20字），用于抒情/环境/思考
  交替:                   快-慢-快，制造节奏感

## 场景节奏
  动作场景:               快节奏，短句，少描写，多动作
  日常场景:               中等节奏，对话为主，穿插描写
  抒情场景:               慢节奏，长句，多描写，少对话
  揭秘场景:               快慢交替，制造悬念感


# ════════════════════════════════════════════════════════════
#  七、情感处理
# ════════════════════════════════════════════════════════════

## 基础原则
  不直接说:               角色不说"我很难过"，通过动作和细节表现
  不过度渲染:             不堆砌悲伤词汇
  通过行动:               情感通过角色的行动表现
  通过细节:               情感通过小细节流露

## 情感类型处理
  悲伤:                   不写"他哭了"，写"他转身，肩膀抖了一下"
  愤怒:                   不写"他很生气"，写"他捏紧拳头，指甲陷进肉里"
  快乐:                   不写"他很高兴"，写"他嘴角翘起来，脚步都轻了"
  恐惧:                   不写"他很害怕"，写"他后退一步，手不自觉地抖"

## 禁忌
  不许虐主:               不为了感人而虐主角
  不许无脑催泪:           不用死亡/离别强行煽情
  不许说教:               不通过角色之口说"人生道理"


# ════════════════════════════════════════════════════════════
#  八、描写手法
# ════════════════════════════════════════════════════════════

## 环境描写
  原则:                   服务于情节和情绪，不为描写而描写
  密度:                   适中，不堆砌
  角度:                   通过主角的感官描写（看到/听到/闻到/触到）

## 人物描写
  原则:                   通过行动和对话展现性格，不直接说"他是一个XXX的人"
  密度:                   主角多，配角少
  技巧:                   用标志性动作/口头禅/习惯来塑造

## 动作描写
  原则:                   简洁有力，不拖沓
  密度:                   关键动作详细，次要动作一笔带过
  技巧:                   用动词，少用形容词

## 心理描写
  原则:                   通过行动和细节表现，不直接写内心独白
  密度:                   适量，不堆砌
  技巧:                   用"他想"、"他意识到"等引导


# ════════════════════════════════════════════════════════════
#  九、对话风格
# ════════════════════════════════════════════════════════════

## 基础原则
  口语化:                 对话要像真人说话
  个性化:                 每个角色的对话风格不同（参考说话风格规范）
  简洁:                   对话要短，不啰嗦
  有信息量:               每句话都要有信息或推进情节

## 对话格式
  引号:                   用中文引号""
  提示语:                 位置灵活（前/后/中/省略）
  省略:                   熟人之间可省略提示语

## 禁忌
  不许说教:               角色不通过对话讲道理
  不许解说:               角色不通过对话解释剧情
  不许独白:               角色不通过大段独白表达情感


# ════════════════════════════════════════════════════════════
#  十、幽默风格
# ════════════════════════════════════════════════════════════

## 核心类型
  反差萌:                 末世+欢乐，大佬+日常，严肃+搞笑
  吐槽:                   主角/中枢的吐槽是标志性风格
  误会:                   信息差造成的搞笑
  日常崩坏:               日常生活中的搞笑细节

## 幽默密度
  日常章:                 每500字至少1个笑点
  战斗章:                 每1000字至少1个笑点（缓解紧张）
  揭秘章:                 每2000字至少1个笑点（调节气氛）

## 禁忌
  不许低俗:               不用屎尿屁等低俗笑料
  不许尴尬:               不用强行搞笑
  不许破坏人设:           不为了搞笑让角色OOC


# ════════════════════════════════════════════════════════════
#  十一、爽点落地
# ════════════════════════════════════════════════════════════

## 爽点类型
  打脸爽:                 逆袭、反杀、以弱胜强
  升级爽:                 突破、觉醒、获得新能力
  救人爽:                 关键时刻赶到、逆转局势
  揭秘爽:                 真相揭晓、身份曝光、伏笔回收
  规模爽:                 大场面、史诗感、全景展示

## 爽点密度
  每章:                   至少1个S级爽点落地
  每30章:                 1个S级爽点高潮
  卷末:                   1个S级爽点收束

## 爽点写法
  铺垫:                   至少3章铺垫（制造期待）
  爆发:                   短句连发，节奏加快
  余韵:                   爽点后留1章缓冲（回味）


# ════════════════════════════════════════════════════════════
#  十二、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 说话风格
   - 行文风格 → 角色对话时的语言风格约束
   - 行文风格.forbidden_styles → 说话风格.forbidden_patterns

2. 角色档案
   - 行文风格 → 角色性格的表现方式
   - 行文风格.emotional_depth → 角色情感的表达深度

3. 场景切片
   - 行文风格 → 注入prompt（语言风格约束）
   - 行文风格.scene_pacing → 场景节奏控制

4. 细纲
   - 行文风格 → 细纲生成时的语言风格约束
   - 行文风格.chapter_tone → 章节基调设定

5. 上下文引擎
   - 行文风格 → 注入prompt（~200 tokens）
   - 帮助LLM生成符合风格的正文

## Token预算分配

行文风格占Token预算的2%（约2560 tokens for 128K context）：

  当前章节行文风格：~1500 tokens
  行文风格规则：~1060 tokens
