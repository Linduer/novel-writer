# ============================================================
# 时间线格式规范 v1.0
# 管理故事的时间轴，防止时间冲突
# ============================================================

# ════════════════════════════════════════════════════════════
#  一、为什么需要时间线
# ════════════════════════════════════════════════════════════

长篇小说时间跨度大，不管理时间线会：
  1. 角色年龄前后矛盾
  2. 事件时间顺序混乱
  3. 同一时间发生太多事
  4. 伏笔的引入/回收时间对不上

# ════════════════════════════════════════════════════════════
#  二、字段分级
# ════════════════════════════════════════════════════════════

## Tier1 基础性（绝对不可偏离）

  time_id                时间点ID（tNNNN格式）
  chapter                对应章节（chNNNN格式）
  absolute_time          绝对时间（如"洪水第九日"）
  relative_time          相对时间（如"故事开始后第30天"）
  event                  核心事件（一句话）
  location               发生地点

## Tier2 可演变（随剧情自然变化）

  characters_involved    涉及角色列表
  causality              因果关系（因为A所以B）
  timeline_branch        时间线分支（如果有平行时间线）
  duration               持续时间（如果事件跨多章）

## Tier3 可偏离（根据行文情况调整）

  atmosphere             时间点的氛围
  significance           时间点的重要性（1-10）


# ════════════════════════════════════════════════════════════
#  三、时间体系
# ════════════════════════════════════════════════════════════

## 绝对时间体系（故事内时间）

故事从"洪水第一天"开始，以"洪水第N日"为主要时间单位。

| 时间单位 | 说明 | 示例 |
|----------|------|------|
| 洪水第N日 | 主要时间单位 | 洪水第九日（就籍日） |
| 卷 | 故事卷 | 卷一、卷二... |
| 月 | 自然月 | 故事开始后第X月 |
| 年 | 自然年 | 故事跨约一年 |

## 相对时间体系（章节时间）

以章节为单位的时间轴：

| 章节范围 | 故事时间 | 说明 |
|----------|----------|------|
| ch001-096 | 洪水第1日-第96日 | 卷一 |
| ch097-192 | 洪水第97日-第192日 | 卷二 |
| ch193-288 | 洪水第193日-第288日 | 卷三 |
| ch289-384 | 洪水第289日-第384日 | 卷四 |
| ch385-480 | 洪水第385日-第480日 | 卷五 |
| ch481-576 | 洪水第481日-第576日 | 卷六 |
| ch577-672 | 洪水第577日-第672日 | 卷七 |
| ch673-768 | 洪水第673日-第768日 | 卷八 |
| ch769-864 | 洪水第769日-第864日 | 卷九 |
| ch865-960 | 洪水第865日-第960日 | 卷十 |

## 水位刻度（全书倒计时）

水位是故事的"时钟"，代表渊的围城进度：

| 水位 | 章节 | 说明 |
|------|------|------|
| 开局水位 | ch001 | 初始水位 |
| 第四级 | ch382 | 大陆架没顶 |
| 退潮开始 | ch759-762 | 水位开始下降 |
| 终战水位 | ch864 | 最高水位 |
| 免票水位 | ch959 | 最终水位 |


# ════════════════════════════════════════════════════════════
#  四、字段说明
# ════════════════════════════════════════════════════════════

## 基础信息
- time_id:           时间点ID（tNNNN格式）
- chapter:           对应章节（chNNNN格式）
- absolute_time:     绝对时间（如"洪水第九日"）
- relative_time:     相对时间（如"故事开始后第30天"）
- event:             核心事件（一句话）
- location:          发生地点

## 关联信息
- characters_involved: 涉及角色列表
- causality:         因果关系（因为A所以B）
- duration:          持续时间（如果事件跨多章）

## 元信息
- timeline_branch:   时间线分支（如果有平行时间线）
- atmosphere:        时间点的氛围
- significance:      时间点的重要性（1-10）

#  六、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 章节记忆
   - 每章的 memory.json 中的时间信息 → 时间线
   - 时间线的 chapter → 章节的 metadata

2. 伏笔系统
   - 时间线的 time_id → 伏笔的引入/推进/回收章节
   - 时间线的 causality → 伏笔的因果关系

3. 角色档案
   - 时间线的 characters_involved → 角色的 appearances
   - 时间线的 event → 角色的 growth_arc

4. 地点档案
   - 时间线的 location → 地点的 key_events

5. 上下文引擎
   - 当前章节的时间线信息 → 注入prompt
   - 帮助LLM理解时间顺序
