# ============================================================
# 细纲格式规范 v1.0
# 每章的生成prompt，指导LLM如何写这一章
# ============================================================

# ════════════════════════════════════════════════════════════
#  一、细纲的作用
# ════════════════════════════════════════════════════════════

细纲是LLM写章节时的直接参考，包含：
  1. 这一章要写什么（剧情目标）
  2. 这一章有哪些人（出场角色）
  3. 这一章发生在哪（场景地点）
  4. 这一章的情绪走向（情绪曲线）
  5. 这一章的爽点设计（爽点安排）
  6. 这一章要推进的伏笔（伏笔管理）
  7. 这一章的约束条件（注意事项）

# ════════════════════════════════════════════════════════════
#  二、字段分级
# ════════════════════════════════════════════════════════════

## Tier1 基础性（绝对不可偏离）

  chapter               章节号（chNNNN格式）
  chapter_title         章节标题
  volume                所属卷号
  core_event            核心事件（一句话）
  pov                   视角人物
  location              主要地点
  characters            出场角色列表
  word_count            目标字数

## Tier2 可演变（随剧情自然变化）

  plot_objective        剧情目标（这一章要完成什么）
  emotion_curve         情绪曲线（开始→中间→结束）
  tension_level         紧张度（1-10）
  satisfaction_points   爽点设计
  foreshadows           本章要推进的伏笔
  character_changes     角色状态变化
  constraints           注意事项/禁忌

## Tier3 可偏离（根据行文情况调整）

  scene_list            场景列表（每章的场景安排）
  opening_hook          开篇钩子（怎么开头）
  ending_hook           结尾钩子（怎么结尾，让读者想看下一章）
  style_notes           风格说明
  reference_chapters    参考章节（可以参考哪些已写章节）


# ════════════════════════════════════════════════════════════
#  三、字段说明
# ════════════════════════════════════════════════════════════

## 基础信息
- chapter:            章节号（chNNNN格式）
- chapter_title:      章节标题
- volume:             所属卷号
- core_event:         核心事件（一句话）
- pov:                视角人物
- location:           主要地点
- characters:         出场角色列表
- word_count:         目标字数

## 剧情规划
- plot_objective:     剧情目标（这一章要完成什么）
- emotion_curve:      情绪曲线
  - start:            开始时的情绪
  - middle:           中间时的情绪
  - end:              结束时的情绪
- tension_level:      紧张度（1-10）
- satisfaction_points: 爽点设计（数组）

## 伏笔管理
- foreshadows:        本章要推进的伏笔（数组）
  - foreshadow_id:    伏笔ID（fsNNN）
    action:           动作（introduce/advance/resolve）
    description:      本章如何处理这个伏笔

## 角色变化
- character_changes:  角色状态变化（数组）
  - character:        角色名
    change:           变化描述
    type:             变化类型（realm/ability/relationship/status/item）

## 场景安排
- scene_list:         场景列表（数组，与场景切片格式对应）
  - order:            场景顺序
    location:         场景地点
    characters:       场景人物
    event:            场景事件
    emotion:          场景情绪
    tension:          场景紧张度

## 开篇与结尾
- opening_hook:       开篇钩子（怎么开头，吸引读者）
- ending_hook:        结尾钩子（怎么结尾，让读者想看下一章）

## 注意事项
- constraints:        注意事项/禁忌（数组）
- style_notes:        风格说明
- reference_chapters: 参考章节（可以参考哪些已写章节）


# ════════════════════════════════════════════════════════════
#  四、取值表
# ════════════════════════════════════════════════════════════

## emotion（情绪类型）

| 值        | 说明     | 适用场景            |
|-----------|----------|---------------------|
| 平静      | 日常     | 过渡、交代          |
| 轻松      | 搞笑     | 日常、吐槽          |
| 紧张      | 危机     | 战斗、逃亡          |
| 悲伤      | 离别     | 死亡、分手          |
| 愤怒      | 冲突     | 争吵、对峙          |
| 喜悦      | 胜利     | 突破、成功          |
| 恐惧      | 危险     | 面对强敌            |
| 震惊      | 反转     | 真相揭露            |
| 温暖      | 感动     | 守护、牺牲          |
| 绝望      | 低谷     | 真败、至暗时刻      |
| 释然      | 放下     | 和解、告别          |
| 决心      | 抉择     | 重大决定            |

## satisfaction_points（爽点类型）

| 值     | 说明       |
|--------|------------|
| 打脸   | 证明对方错了 |
| 装逼   | 展示隐藏实力 |
| 反转   | 剧情180度转弯 |
| 逆袭   | 从弱到强 |
| 收获   | 获得新能力/物品/伙伴 |
| 守护   | 保护重要的人 |
| 牺牲   | 为他人付出 |
| 团聚   | 分离后重逢 |
| 揭秘   | 真相大白 |
| 报仇   | 复仇成功 |
| 成就   | 达成重要目标 |
| 认可   | 被重要人物认可 |

## character_changes.type（变化类型）

| 值         | 说明       |
|------------|------------|
| realm      | 境界突破   |
| ability    | 能力获得   |
| relationship | 关系变化 |
| status     | 状态变化   |
| item       | 物品获取   |

# ════════════════════════════════════════════════════════════
#  六、与LLM的集成
# ════════════════════════════════════════════════════════════

细纲会直接注入LLM的prompt：

1. 读取当前章节的细纲
2. 提取关键信息（核心事件、出场角色、情绪曲线、约束）
3. 注入到prompt的"本章任务"部分
4. LLM根据细纲生成章节

## Token预算分配

细纲占Token预算的3%（约384 tokens for 128K context）：

  本章核心信息：~200 tokens
  本章场景安排：~100 tokens
  本章约束条件：~84 tokens


# ════════════════════════════════════════════════════════════
#  七、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 大纲
   - 细纲的 volume → 大纲的 volumes
   - 细纲的 core_event → 大纲的 key_events

2. 场景切片
   - 细纲的 scene_list → scenes.json
   - 细纲的 emotion_curve → 场景的 emotion

3. 伏笔系统
   - 细纲的 foreshadows → 伏笔的推进/回收
   - 细纲的 foreshadow_id → 伏笔的 ID

4. 角色档案
   - 细纲的 characters → 角色档案的 name
   - 细纲的 character_changes → 角色档案的 growth_arc

5. 爽点审查
   - 细纲的 satisfaction_points → 爽点审查的记录
   - 细纲的 emotion_curve → 爽点审查的节奏分布

6. 别名系统
   - 细纲的 characters → 别名系统（生成时注入当前章节的称呼信息）
   - 细纲生成对话时必须参考别名系统的 self_call 和 forbidden_calls

7. 说话风格
   - 细纲生成对话时必须参考说话风格的 signature_style 和 forbidden_patterns
   - 细纲的 character_changes.type=personality → 可能影响说话风格

8. 能力体系
   - 细纲的 character_changes.type=realm → 能力体系.境界突破
   - 细纲的 character_changes.type=ability → 能力体系.天赋/设施解锁

9. 物品格式规范
   - 细纲生成时如果涉及物品获取/使用 → 必须参考物品格式规范
   - 细纲的 character_changes.type=item → 物品格式规范的状态更新

10. 时间线
    - 细纲的 chapter → 时间线的时间点
    - 细纲的核心事件 → 时间线的记录

11. 上下文引擎
    - 细纲的当前章信息 → 注入prompt
    - 帮助LLM理解这一章该写什么
