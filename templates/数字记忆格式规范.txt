# ════════════════════════════════════════════════════════════
#  一、为什么需要数字记忆
# ════════════════════════════════════════════════════════════

上下文压缩（摘要）会丢失精确数字，但后续章节可能需要引用：

  第50章提到密码是"7924"
  → 压缩后变成"主角打开了一个锁"
  → 第500章需要再次输入密码
  → LLM不知道密码是什么
  → 数字记忆模块解决这个问题

核心原则：数字是精确的，不能被摘要模糊化。


# ════════════════════════════════════════════════════════════
#  二、数字类型分类
# ════════════════════════════════════════════════════════════

## Tier1 关键数字（绝对不可丢失）

| 类型 | 说明 | 示例 |
|------|------|------|
| password | 密码/暗号 | 锁密码7924、保险箱密码 |
| code | 代码/指令 | 启动代码、解锁代码 |
| coordinate | 坐标/位置 | 经纬度、藏宝坐标 |
| date | 日期/生日 | 角色生日、纪念日、事件日期 |
| amount | 金额/数量 | 债务金额、物资数量 |
| time | 时间/时限 | 倒计时、截止时间、冷却时间 |

## Tier2 重要数字（尽量保留）

| 类型 | 说明 | 示例 |
|------|------|------|
| measurement | 测量值 | 水位高度、距离、温度 |
| count | 计数 | 人数、次数、层数 |
| ratio | 比例/概率 | 胜率、成功率、兑换率 |
| sequence | 序列/编号 | 房间号、楼层、序列号 |

## Tier3 参考数字（可被摘要）

| 类型 | 说明 | 示例 |
|------|------|------|
| estimate | 估算值 | "大概一百多"、"几千" |
| description | 描述性数字 | "跑了三圈"、"想了半天" |
| comparison | 比较性数字 | "比之前多了两倍" |


# ════════════════════════════════════════════════════════════
#  三、字段分级
# ════════════════════════════════════════════════════════════

## Tier1 基础性（绝对不可偏离）

  id                    数字ID（num_NNN格式，唯一标识）
  value                 数字值（精确值，字符串格式）
  type                  数字类型（见取值表）
  context               数字含义（一句话说明这个数字是什么）
  introduced_in         首次出现章节（chNNNN格式）
  related_characters    关联角色列表

## Tier2 可演变（随剧情自然变化）

  current_value         当前值（数字可能变化，如密码被修改）
  change_history        变化历史（数组，记录每次变化）
  last_used_in          最后使用章节
  status                状态（active/changed/expired/used）

## Tier3 可偏离（根据行文情况调整）

  aliases               数字的别称（如"七九二四"也叫"7-9-2-4"）
  notes                 备注信息
  hint_text             提示文本（如何暗示这个数字）


# ════════════════════════════════════════════════════════════
#  四、取值表
# ════════════════════════════════════════════════════════════

## type（数字类型）

| 值            | 说明         | 示例                    |
|---------------|--------------|-------------------------|
| password      | 密码/暗号    | 锁密码7924              |
| code          | 代码/指令    | 启动代码                |
| coordinate    | 坐标/位置    | 藏宝坐标                |
| date          | 日期/生日    | 角色生日                |
| amount        | 金额/数量    | 债务八百万              |
| time          | 时间/时限    | 倒计时30天              |
| measurement   | 测量值       | 水位高度                |
| count         | 计数         | 人数、次数              |
| ratio         | 比例/概率    | 胜率60%                 |
| sequence      | 序列/编号    | 房间号302               |

## status（数字状态）

| 值      | 说明           |
|---------|----------------|
| active  | 当前有效       |
| changed | 已被修改       |
| expired | 已过期/失效    |
| used    | 已使用（一次性）|


# ════════════════════════════════════════════════════════════
#  五、字段说明
# ════════════════════════════════════════════════════════════

## 基础信息
- id:                 数字ID（num_NNN格式）
- value:              数字值（精确值，字符串格式，如"7924"、"八百万"）
- type:               数字类型（见取值表）
- context:            数字含义（一句话说明这个数字是什么）
- introduced_in:      首次出现章节（chNNNN格式）
- related_characters: 关联角色列表

## 状态追踪
- current_value:      当前值（数字可能变化）
- change_history:     变化历史（数组，每项包含 chapter/old_value/new_value/reason）
- last_used_in:       最后使用章节
- status:             当前状态

## 辅助信息
- aliases:            数字的别称（如"7924"也叫"七九二四"）
- notes:              备注信息
- hint_text:          提示文本（如何暗示这个数字）

# ════════════════════════════════════════════════════════════
#  七、数字记忆管理规则
# ════════════════════════════════════════════════════════════

## 提取规则

1. **自动提取**：LLM在生成章节记忆时，自动识别并提取特殊数字
2. **手动标记**：作者可以在章节中标记需要记忆的数字
3. **重复确认**：如果数字在多个章节出现，确认是否为同一个数字

## 注入规则

1. **当前章出场数字**：如果当前章需要用到某个数字，必须注入
2. **伏笔相关数字**：如果数字与活跃伏笔相关，必须注入
3. **角色相关数字**：如果数字与当前出场角色相关，必须注入

## 更新规则

1. **数字变化**：如果数字被修改，记录变化历史
2. **数字使用**：如果数字被使用，更新 last_used_in
3. **数字过期**：如果数字失效，更新 status 为 expired

## 压缩保护

1. **摘要保留**：数字记忆不会被摘要压缩，始终保留精确值
2. **Token预算**：数字记忆占Token预算的2%（约256 tokens for 128K context）
3. **优先级**：Tier1 > Tier2 > Tier3


# ════════════════════════════════════════════════════════════
#  八、与其他系统的关联
# ════════════════════════════════════════════════════════════

1. 章节记忆
   - 每章 memory.json 中的 numbers 字段 → 数字记忆的引入/使用
   - 数字记忆 → 不会被摘要压缩，始终保留

2. 伏笔系统
   - 数字记忆.value → 伏笔的引入/推进/回收
   - 数字记忆的使用 → 伏笔的推进记录

3. 角色档案
   - 数字记忆.related_characters → 角色的秘密/背景
   - 数字记忆的使用 → 角色的 growth_arc

4. 时间线
   - 数字记忆.introduced_in → 时间线的时间点
   - 数字记忆的使用 → 时间线的事件记录

5. 场景切片
   - 数字记忆的使用 → 场景切片的 event
   - 数字记忆 → 场景的 tension_level

6. 细纲
   - 细纲生成时需要用到数字 → 必须参考数字记忆
   - 细纲的 foreshadows 可能涉及数字记忆

7. 上下文引擎
   - 当前章节需要用到的数字 → 注入prompt
   - 数字记忆不会被压缩，始终保留精确值

8. 爽点审查
   - 数字的揭晓 → 爽点的揭秘类型
   - 数字的使用 → 爽点的铺垫
