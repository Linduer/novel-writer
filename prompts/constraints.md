# 约束体系说明

本系统使用三级约束体系，确保行文一致性。冲突时高档约束优先。

## 约束等级

### 第一档：已写定（TIER_1_IMMUTABLE）— 绝对不可违背

已写入正文的事实，包括但不限于：
- 角色名称、性格、口头禅、说话风格
- 角色间关系（敌对/合作/师徒/暧昧等）
- 角色当前状态（情绪、能力、伤势、所在位置）
- 已发生的关键事件（不可撤销）
- 已埋设和已回收的伏笔
- 世界观硬设定（能力体系、地理、势力分布）

> 这些内容一旦写定，后续行文**必须保持一致**。
> 如果发现前后矛盾，应修正新写的内容，而非修改已写定的内容。

### 第二档：大纲（TIER_2_OUTLINE）— 原则上不可违背

故事整体规划，包括：
- 卷纲/篇纲的核心剧情走向
- 关键转折点和高潮设计
- 伏笔的预设回收时间
- 角色成长弧线规划
- 世界观扩展路线

> 大纲是长期方向指引。如果正文与大纲冲突，通常应修正正文。
> 但如果发现大纲本身不合理，可以在**不破坏已有剧情**的前提下调整。

### 第三档：细纲（TIER_3_CHAPTER）— 可适度偏离

每章的具体写作提示，包括：
- 本章场景设计
- 对话要点
- 节奏安排
- 具体的伏笔埋设/回收指令

> 细纲在生成时已考虑了前文上下文，可能与原始大纲有偏差。
> 这是正常的。细纲可以灵活调整，但**不能违反第一档和第二档的约束**。

## 冲突解决规则

```
当不同档次的约束发生冲突时：
  1. 第一档 > 第二档 > 第三档
  2. 高档约束无条件优先
  3. 低档约束需主动服从高档约束
  4. 如需违反高档约束，必须手动确认并调整
```

## 自动维护

- **Tier1**：每次 `save` 保存章节时，系统自动从记忆中提取已写定事实
- **Tier2**：导入大纲时自动提取关键约束
- **Tier3**：每次 `write` 生成章节前写入，生成后归档

## 手动补充

可在以下位置手动编辑约束文件：
```
data/{project}/constraints/
  tier1_immutable.json   ← 手动补充关键设定
  tier2_outline.json     ← 手动补充大纲约束
  tier3_chapter.json     ← 通常由系统管理
```
